Refresh Opportunity Scoring

Ranking content pages for human review when deciding where content-refresh attention should be prioritized.

Lane: Refresh / Content Opportunity Scoring Task: Ranking Model: Random Forest Metric: Precision@50

Abstract

This project asks whether a machine-learning ranking model can help prioritize content pages for refresh review based on observed search-performance signals. The analysis uses the FlyRank internship warehouse and evaluates a defined population of content items using previous-30-day performance and query-visibility signals. A Random Forest model is compared with the transparent Week-4 rule-based baseline using Precision@50 on the same evaluation population. The Random Forest achieved 0.86 Precision@50 compared with 0.82 for the baseline, placing 43 observed decline cases in its top 50 recommendations versus 41 for the baseline. The resulting ranking is intended as decision-support for human content review rather than as a causal prediction of search behavior or a guarantee that refreshing a page will recover traffic.

1. Introduction / Problem Statement

Content teams may have many pages that could potentially deserve attention, while editorial time is limited. The practical decision is therefore not simply whether a page changed, but which pages should be reviewed first.

Decision supported:
Prioritize pages for content-refresh review.

The unit of analysis is a content item. The model produces a ranking score that can be used to order content-review candidates. A human reviewer can then investigate the highest-ranked items before deciding whether a refresh is appropriate.

Machine learning is useful here because several search-performance signals can be considered together rather than relying on a single manually chosen rule.

Excluded fields

Label-derived and identity fields were deliberately excluded from predictive inputs. This includes trend_direction, client_hash_id, and content_hash_id. Client and content identifiers were not used as predictive features.

Data-safety principle: The project uses anonymized internship data and does not expose client names, domains, private queries, credentials, or raw client exports.

3. Methodology

Target definition

The target represents whether the content item belongs to the observed impression-decline class between the defined comparison windows.

Model

The primary model is a Random Forest classifier. Its predicted probability is used as a ranking score rather than treating the output as an automatic editorial decision.

Baseline

The model is compared against the transparent Week-4 rule-based baseline. Both methods are evaluated using the same evaluation population and the same Precision@50 metric.

Validation design

The evaluation uses a 75/25 stratified train/test split with random_state=42. The stratified design preserves the observed class proportions between the training and evaluation partitions.

The evaluation should therefore be interpreted as performance on this defined historical sample rather than as a future-period time-series forecast.

5. Limitations & Honest Framing

This analysis has several important limitations.

  • The evaluation describes the defined sample and should not automatically be generalized to all websites or future periods.
  • The target represents an observed impression decline. It does not establish why the decline happened.
  • Precision@50 measures ranking quality for observed decline cases. It does not measure whether a content refresh would actually recover traffic or improve search performance.
  • Random Forest feature importance describes model reliance on signals in this sample and should not be interpreted as causality.
  • The ranked output is decision-support for content review, not an automatic instruction to rewrite, delete, or change content.
Important: This project does not claim to predict Google's algorithm, prove causal relationships, or guarantee the outcome of a content refresh.

6. Ranked Recommendations

The model output is intended to prioritize content for human review. Pages with higher model scores are higher-priority candidates because the model estimates a higher likelihood of belonging to the observed decline class.

Review the highest-ranked pages first. Use the model score to focus limited editorial attention on the strongest candidates.
Check historical search performance. Review impressions, clicks, CTR, and query visibility before making a refresh decision.
Investigate whether the decline is meaningful. A high model score is a review signal, not proof that a page needs to be rewritten.
Review pages manually before taking action. Editorial context should determine whether refreshing the page is appropriate.
Monitor unusual or low-confidence cases. Not every ranked item should become an automatic refresh task.

The intended workflow is therefore: rank → investigate → review → decide → act.

Conclusion

The Random Forest produced a modest but measurable improvement over the Week-4 rule-based baseline for ranking observed content declines in the top 50 recommendations.

The main practical value is not an automatic refresh decision. Instead, the model provides a repeatable way to narrow a larger content-review queue so that human attention can start with stronger candidates.

The result should be treated as directional, measured evidence from the evaluation sample and as decision-support rather than proof of causal impact.
